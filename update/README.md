# custom_redir.php v2.1 — обновление

Три файла для трёх типов сайтов. **Ядро у всех одинаковое**, отличается только блок `$CONFIG` в начале файла:

| Файл | Сайт | PHP |
|---|---|---|
| `custom_redir-static-php-8-2.php` | статичный сайт (БФ «МДС») | 7.4 – 8.4 |
| `custom_redir-wp-php-8-2.php` | WordPress (+ кнопка очистки кэша) | 7.4 – 8.4 |
| `custom_redir-bitrix-php-7-4.php` | 1С-Битрикс, zdoroviymalysh.ru | 7.4 – 8.4 |

За основу взята версия из `update-test/`. Её проверили на живом Apache, нашли дефекты и исправили их здесь (список ниже).

## Как обновить

1. Заменить на сайте старый `custom_redir.php` файлом нужного типа, **имя файла оставить прежним**. Блок `$CONFIG` уже заполнен так же, как в `update-test/`.
2. Войти в панель. Старые редиректы подхватятся автоматически, сверху появится жёлтая плашка «Редиректов без исключения ботов: N».
3. Нажать **«Применить ко всем»**. Все старые редиректы пересоберутся с исключением ботов. Перед записью делается резервная копия, после записи сайт проверяется, и при ошибке изменение откатывается само.
4. У любого редиректа нажать **«Проверить»**. Панель покажет, что видят обычный посетитель, посетитель из приложения Яндекса, Яндекс Директ, Метрика, поисковые роботы Яндекса и Google.

Если плашка появится снова (например, после следующего обновления скрипта со свежим списком ботов), нужно снова нажать «Применить ко всем».

## Как устроено исключение ботов

- Список ботов хранится в `.htaccess` **один раз**, в служебном блоке `# @cr-bots`. Этот блок ставит признак `CUSTOM_REDIR_BOT`, а каждый редирект проверяет только этот признак.
- Роботы Яндекса определяются по подписи `yandex.com/bots` (она есть у всех официальных роботов, в том числе у будущих) и по именам роботов: `YaDirectFetcher`, `YandexDirect`, `YandexMetrika`, `YandexBot` и т. д. (всего 37 сигнатур Яндекса).
- Подстрока `Yandex` сама по себе **намеренно не используется**: она встречается у настоящих посетителей из старого приложения Яндекса (`YandexSearch/…`). Они должны получать редирект: это трафик Директа.
- Новый бот добавляется в панели, в поле «Свои правила», и сразу применяется ко всем редиректам, включая старые. Поле «Проверить User-Agent» показывает, считается ли строка ботом.
- Кнопка «Копия» у редиректа заполняет форму добавления, например чтобы быстро сделать такой же редирект с другой меткой.

## Что исправлено относительно `update-test/`

|---|---|---|---|
| 1 | Полный список ботов (117 сигнатур, около 1,7 КБ) копировался в каждый редирект | Apache разбирает `.htaccess` на каждый запрос. ## Что было не так в старых версиях (до `update-test`) — для справки

Все эти ошибки воспроизведены на Apache, в v2 их нет:

- **static / WP:** добавление любого нового редиректа портило уже существующие, у которых в адресе или метке есть `-` или `.` (`how-help` превращался в `how\\-help`, и редирект переставал работать). v2 такие записи чинит при чтении.
- **static / WP:** пробел в адресе или многострочный комментарий роняли весь сайт в 500.
- **WP:** блок дописывался в конец `.htaccess`, ниже правил WordPress, поэтому редиректы с внутренних страниц не срабатывали. v2 переносит блок выше.
- **WP:** `?clear_cache` работал **без пароля**, любой мог сбрасывать кэш WP Rocket.
- **Все:** ботам (YaDirectFetcher, YandexMetrika и остальным) отдавался 301. Удаление было по GET-ссылке без защиты от CSRF.
- **static / WP:** ошибки сохранения показывались зелёным, как «успех».

## Как проверялось

- Apache 2.4.58 + PHP 8.3 (mod_php): три тестовых сайта (статичный, WordPress с WP Rocket, Битрикс с блоклистом IP и `urlrewrite.php`) и два «плохих» хостинга: запрещён `RewriteEngine` (500) и выключен `FollowSymLinks` (403). В обоих случаях сработал автооткат.
- Матрица из 39 User-Agent на каждый редирект: 11 реальных посетителей (приложение Яндекса старое и новое, Яндекс Браузер, Telegram, VK, Instagram, телефон Cubot и др.) и 28 ботов (все роботы Директа, Метрики и поиска Яндекса, Google, соцсети, пустой UA и др.). Везде 39/39.
- Миграция из трёх форматов: старые скрипты (включая испорченные записи), `update-test` v2.0 и пример `custom_redir-new.php`.
- 22 граничных случая ввода: кириллица, якоря, `?` в цели, пробелы, переводы строк, `\`, `$` и `%` в адресах, дубли, циклы.
- PHP 7.4.33 и 8.2.10 (WASM-сборки) — полный сценарий работы панели без единого предупреждения PHP; `php -l` на 7.4, 8.2, 8.3 и 8.4.
